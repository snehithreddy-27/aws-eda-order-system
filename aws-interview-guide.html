SNS
Simple Notification Service
Tier 1
Fan-out — one message, many receivers
What it does
Publishes one message to a topic. SNS copies it to every subscriber instantly — queues, Lambdas, emails — all at the same time.
Why you use it
When one event triggers many services. Order placed → payment + email + inventory all fire in parallel. Decoupled and fast.
Interview answer
"SNS is a pub/sub messaging service. One publisher sends to a topic, SNS fans it out to all subscribers simultaneously. I used it so a single order.placed event triggered payment, email, and inventory — all in parallel, completely decoupled."
✓ fan-out to multiple services✓ real-time notifications✗ one consumer → use SQS direct
SQS
Simple Queue Service
Tier 1
Message queue — buffer between services
What it does
Holds messages in a durable queue. Messages never disappear even if the consumer crashes. At-least-once delivery guaranteed.
Why you use it
Decouples services. Producer fires and forgets. Consumer processes when ready. Absorbs traffic spikes without losing data.
Interview answer
"SQS is a managed message queue. It decouples producer from consumer — producer drops a message and moves on, consumer processes it when ready. In my project each microservice had its own queue so a slow payment processor never blocked the email service."
✓ async processing✓ absorb traffic spikes✗ multiple consumers → fan-out with SNS first
Lambda
Serverless compute
Tier 1
Event triggered — wake up, run, sleep
What it does
Runs your code on demand triggered by SQS, API Gateway, S3, timers. Wakes up, executes, stops. Zero servers to manage.
Why you use it
Pay only for actual execution time. No idle cost. Auto-scales from 1 to 10,000 concurrent runs instantly. Perfect for events.
Interview answer
"Lambda is AWS's serverless compute service. You deploy code and AWS handles the servers, scaling, and patching. I used Lambda as the consumer for each SQS queue — when an order event arrives, Lambda wakes up, processes it, writes to DynamoDB, and sleeps. Zero server management."
✓ short event-driven tasks✓ variable or unpredictable load✗ tasks over 15 min → use EC2 or ECS
IAM
Identity and Access Management
Tier 1
Permissions — who can do what
What it does
Controls who can do what in AWS. Roles, policies, and users. A Lambda needs a role to read SQS — IAM grants exactly that and nothing more.
Why you use it
Security and least privilege. If credentials leak, damage is limited to what that role can do. Every AWS service needs an IAM permission to touch another.
Interview answer
"IAM is AWS's permission system. I created lambda-order-role with only two policies — SQS read and CloudWatch write. That's it. My Lambda can't touch S3 or EC2. This is the principle of least privilege — a fundamental security best practice. If the role is compromised, blast radius is tiny."
✓ always — every AWS resource needs IAM✗ never use root for daily work
S3
Simple Storage Service
Tier 1
Object storage — files at infinite scale
What it does
Stores any file — JSON, HTML, images, PDFs — in buckets. Infinitely scalable. Can host static websites directly without a server.
Why you use it
Cheapest storage on AWS. 99.999999999% durability. I used it to host the architecture website and store order receipt files after payment.
Interview answer
"S3 is object storage — an infinitely large cloud hard drive. I used it two ways: hosting my static architecture demo site (no server needed), and storing order receipt JSON files after payment. S3 has 11 nines of durability — it essentially never loses a file. It's not for structured queryable data though — that's DynamoDB."
✓ files, images, HTML, receipts✓ static website hosting✗ structured queries → DynamoDB or RDS
CloudWatch
Monitoring and observability
Tier 1
Logs + metrics + alarms
What it does
Collects logs, metrics, and events from every AWS service automatically. Lets you see what happened, when, and alerts you when things break.
Why you use it
Without it you're flying blind. When Lambda fails, CloudWatch shows the exact error line. You can set alarms that email you before users notice problems.
Interview answer
"CloudWatch is AWS's observability platform. It collects logs from Lambda automatically — I could see my Python print() statements in real time. You can create metric alarms: if Lambda error rate exceeds 5% for 5 minutes, trigger an SNS alert and email the on-call engineer. It's how you know your system is healthy."
✓ always — Lambda logs here automatically✓ set alarms on error rates, latency
Tier 2 — understand clearly and explain confidently
API Gateway
Managed HTTP API front door
Tier 2
Routes HTTP requests to the right Lambda
What it does
Single HTTPS entry point for all API calls. Routes each URL path to the right Lambda. Handles auth, SSL, rate limiting, CORS automatically.
Why you use it
Replaces EC2 + Load Balancer for APIs. Fully managed. Scales to millions of requests. Costs nothing when idle — pay per request only.
Interview answer
"API Gateway is the fully managed front door for HTTP APIs. It receives all requests, handles auth and rate limiting, then routes to the right Lambda based on the URL path. GET /products goes to product-lambda, POST /basket/checkout goes to basket-lambda. No EC2 or load balancer needed — fully serverless."
✓ REST APIs with Lambda backend✓ public-facing microservices✗ internal service-to-service → direct Lambda invoke
DynamoDB
Serverless NoSQL database
Tier 2
Key-value store — millisecond reads at any scale
What it does
Fully managed NoSQL database. Stores JSON items identified by a primary key. Single-digit millisecond reads at any scale. No servers.
Why you use it
One table per microservice — database-per-service pattern. Services never share databases so one slow query can't impact others.
Interview answer
"DynamoDB is AWS's serverless NoSQL database. It stores JSON items with a primary key. In my microservices project each service has its own table — products-table, baskets-table, orders-table. This is the database-per-service pattern: services never share databases. If orders-table is slow it never affects product lookups."
✓ flexible JSON data per service✓ high-speed key lookups✗ complex SQL joins → use RDS
EventBridge
Advanced event bus with rules
Tier 2
Content-based routing — smarter than SNS
What it does
Routes events using content-based rules. Reads the event body and routes to different targets based on what's inside. Far more precise than SNS.
Why over SNS?
SNS broadcasts to all. EventBridge filters by content. Only checkout events hit the order queue. Shipping events route elsewhere. Much cleaner architecture.
Interview answer
"EventBridge is an advanced event bus with content-based routing. Unlike SNS which broadcasts to all subscribers, EventBridge uses rules — if source is basket-service AND type is checkout, route to SQS. One event can go to different targets based on what it contains. It also integrates with 200+ AWS and SaaS services natively."
✓ complex routing logic needed✓ SaaS integration (Stripe, Salesforce)✗ simple fan-out → SNS is simpler
EC2
Elastic Compute Cloud
Tier 2
Virtual server — you SSH in and run anything
What it does
Gives you a virtual computer in AWS. Pick OS, CPU, RAM. SSH in, install anything, run your app. Runs until you stop it.
When to use it
When you need full server control — long-running processes, custom OS config, or workloads over 15 minutes that Lambda can't handle.
Interview answer
"EC2 is virtual machine hosting. You choose instance type — t3.micro has 2 vCPU and 1GB RAM — and AWS gives you a server to SSH into. I chose Lambda over EC2 for my order system because orders are short events. But for a long-running background job, a traditional web server, or anything needing full OS control, EC2 is the right choice."
✓ long-running processes✓ full OS and environment control✗ short event tasks → Lambda cheaper
VPC
Virtual Private Cloud
Tier 2
Your private network — public and private subnets
What it does
Creates an isolated private network inside AWS. Divides resources into public subnets (internet-accessible) and private subnets (internal only).
Why you use it
Network security. Your database should never be publicly accessible. VPC puts it in a private subnet — only your app servers can reach it.
Interview answer
"VPC is your private network inside AWS. The typical pattern: Load Balancer in a public subnet (internet-facing), EC2 app servers in a private subnet, RDS database in a private subnet with zero internet access. Without VPC, your database would be exposed to the public internet. VPC is the network security layer for all EC2 and RDS workloads."
✓ always when using EC2 or RDS✓ isolate databases from internet
ECS
Elastic Container Service
Tier 2
Container orchestration — runs your Docker images
What it does
Runs and manages Docker containers. You define a task (which image to run), ECS starts it, keeps it running, and scales it. With Fargate — no servers at all.
When to use it
App is containerized and needs to run continuously. More control than Lambda, less overhead than raw EC2. Natural next step after Dockerizing your app.
Interview answer
"ECS is AWS's container orchestration service. You push a Docker image to ECR (AWS's container registry) and ECS runs it. With Fargate you don't manage any servers. It sits between Lambda — fully serverless, short tasks — and EC2 — full server, always on. For my next project I plan to Dockerize my microservices and deploy them on ECS Fargate."
✓ Dockerized microservices✓ long-running containerized apps✗ simple functions → Lambda is easier
